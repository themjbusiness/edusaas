# EduSaas: instructions for Claude and other coding agents

EduSaas is an AI LMS for FBISE colleges in Pakistan. When a student is absent, they get the exact textbook lesson they missed as a narrated page ("Lesson Object") and must pass a quiz to be cleared. The parent gets a WhatsApp alert and the teacher sees a green tick. It is sold B2B to colleges.

## Documents

- **Every document you write goes in [docs/](docs/) as a Markdown (`.md`) file.** This covers plans, roadmaps, research, specs, reports, change registers and meeting notes. Do not create Claude Docs, hosted artifacts or Word files for project documents unless the user asks for that format.
- Name files in kebab-case (`docs/offline-sync-design.md`). Put feature specs in `docs/features/F<N>-<short-name>.md`, copied from [docs/features/_template.md](docs/features/_template.md).
- Add every new document to the table in [docs/README.md](docs/README.md).
- [docs/roadmap.md](docs/roadmap.md) is the plan of record: the feature IDs (F1–F19), phases, gates and the quality process all come from it. Update it when a decision changes it.

## How features are built

Work one feature at a time, following the seven steps in [docs/roadmap.md](docs/roadmap.md#quality-process-for-each-feature):

1. Write the spec in `docs/features/` and get the user's sign-off before writing code.
2. Write acceptance criteria as tests, including at least one test that tries to break an access rule.
3. Build a thin end-to-end slice (model, API, screen, test).
4. Run all tests. A feature is not done until every item in its definition of done is ticked.

## Non-negotiable rules

- **Only registered, linked people can sign in.** A student belongs to a class, a teacher is assigned to classes, and a parent is linked to their own child. Refuse unregistered numbers with a clear message. Enforce role and relationship checks on the server for every endpoint. Never add an "any number works" or shared demo login.
- **Quiz answers never go to the client.** Scoring happens on the server.
- **Content is reviewed before students see it.** Lessons generated by the Content Factory stay `draft` until a subject teacher approves them.
- **Textbook pages are National Book Foundation material.** Keep them internal until permission is granted (change register CR-02).
- **Personal data:** never write phone numbers or OTPs to logs. Never send the user's email address to outside services.

## Project layout

| Path | What it is |
|---|---|
| `content_factory/` | Offline pipeline: textbook PDF → page images, script and quiz (authored JSON or Claude), edge-tts narration → Lesson Objects in `output/` |
| `backend/` | Django 6 API (`lms` app): roster, OTP sign-in, attendance, clearance, quiz scoring, notifications, parent progress, college admin console (`admin_api.py`). Serves the web app. The Django admin panel is for superusers only. |
| `web/` | The web app (F1): React 18 + TypeScript + Vite, served by Django at `/` from `web/dist`. Components in `src/ui`, screens per role in `src/screens`, typed API client in `src/lib/api.ts`, Urdu in `src/i18n/ur.json`, gallery at `/#/gallery`. |
| `media/` | Lesson page images and audio, copied in by `import_lessons`, served at `/media/` |
| `legacy/` | The old vanilla JavaScript app, kept for reference only (not served). Delete when the team agrees. |
| `docs/` | All project documents |
| `start-demo.bat` / `start-demo.sh` | Install, migrate, seed the demo roster and run the server on port 8000 |

## Commands

```text
start-demo.bat                                        # run the demo (resets data; add --keep to keep it)
cd backend && python manage.py test lms               # backend tests (76)
cd content_factory && python -m pytest tests          # Content Factory tests (19)
cd web && npm run build                               # type-check and build the web app into web/dist (served at /)
cd web && npm test                                    # web app unit tests (12)
cd web && npm run dev                                 # dev server on :5173, proxies /api to Django on :8000
cd backend && python manage.py seed_demo              # reset the demo roster (runs seed_catalogue and import_lessons)
cd backend && python manage.py seed_catalogue         # create or update the subject catalogue (Grade 11 and 12)
cd backend && python manage.py send_weekly_summaries  # weekly parent summary (in-app); schedule for Sunday 18:00
cd backend && python manage.py create_college "<name>" --admin-phone 03xxxxxxxxx --admin-name "<name>"
cd backend && python manage.py import_lessons phy11   # load built lessons into the database
```

Demo accounts are listed in [README.md](README.md). The demo college and all `+92 399` numbers are fictional.

## Conventions

- Python: Django, plain function views wrapped by the `@api` decorator in `backend/lms/auth.py`. Every new endpoint declares its allowed roles and scopes its queries to the caller's relationships.
- Every change to access rules or the clearance workflow gets a test in `backend/lms/tests.py`.
- Frontend: mobile-first, design tokens in CSS variables, light and dark mode, touch targets of at least 44 px.
- Frontend code is TypeScript in strict mode; build every screen from the components in `web/src/ui` and the tokens in `web/src/styles.css`, so a redesign changes those, not each screen.
- Student and parent screens are bilingual (F23): wrap every visible English sentence in `t('…', {vars})` (or `tr` for rich text) from `useI18n()` and add the Urdu to `web/src/i18n/ur.json`. Keep book content (lesson titles, questions) as in the textbook. Check right-to-left layout at 360 px.
- Accessibility: no serious or critical axe issues; dim with colour (`--muted`), never with opacity, so text keeps 4.5:1 contrast; use `--accent-ink` for teal text.
- Use Claude model `claude-opus-5-5` for any content generation.
